# github_enterprise_organization_app_installation (Resource)

Manages the installation of a GitHub App on an organization owned by an enterprise, and the repositories that installation can access. The app is installed on the organization rather than on the enterprise account itself, because GitHub offers no API for the latter.

This resource is only available on GitHub Enterprise Cloud, and on GitHub Enterprise Server 3.19 and later.

~> The underlying API can only be called by a GitHub App installed on the enterprise that owns the organization. A personal access token cannot be used, even one belonging to an enterprise owner. Configure the provider for [app authentication](../index.md) with `app_auth.installation_id` set to that enterprise level installation, and leave `owner` unset.

~> GitHub treats installing an app that is already installed as a success, and unsuspends it. Applying this resource against an organization where the app was installed by hand therefore adopts that installation silently, and a later `terraform destroy` uninstalls it. Import a pre-existing installation instead of adopting it.

-> `selected_repositories` must be non-empty when `repository_selection` is `selected`, and must be empty when it is `all` or `none`. Use `none` only when the app requests no repository permissions. GitHub reports these installations as `selected` with an empty repository list; the provider normalizes that response back to `none`.

## Example Usage

```terraform
resource "github_enterprise_organization_app_installation" "ci" {
  enterprise_slug = "my-enterprise"
  organization    = "my-organization"
  client_id       = "Iv23liAbCdEfGhIjKlMn"

  repository_selection = "all"
}

# Restrict the installation to an explicit list of repositories instead.
resource "github_enterprise_organization_app_installation" "deploy" {
  enterprise_slug = "my-enterprise"
  organization    = "my-organization"
  client_id       = "Iv23liOpQrStUvWxYzAb"

  repository_selection  = "selected"
  selected_repositories = ["terraform-modules", "deploy-tooling"]
}

# Install an app that does not request any repository permissions.
resource "github_enterprise_organization_app_installation" "organization_runner" {
  enterprise_slug = "my-enterprise"
  organization    = "my-organization"
  client_id       = "Iv23liCdEfGhIjKlMnOp"

  repository_selection = "none"
}
```

## Schema

### Required

- `client_id` (String) The client ID of the GitHub App to install.
- `enterprise_slug` (String) The slug of the enterprise, as it appears in the enterprise URL.
- `organization` (String) The login of the enterprise owned organization to install the app on.
- `repository_selection` (String) Which repositories the installation can access: `all` for every repository in the organization, or `selected` for the explicit list in `selected_repositories`, or `none` when the app requests no repository permissions.

### Optional

- `selected_repositories` (Set of String) The names of the repositories the installation can access. Required when `repository_selection` is `selected`, and must be empty otherwise.

### Read-Only

- `app_slug` (String) The slug of the installed app.
- `id` (String) The ID of this resource.
- `installation_id` (Number) The numeric ID of the app installation.

## Import

App installations are imported using the enterprise slug, the organization login and the app's client ID, separated by colons.

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
import {
  to = github_enterprise_organization_app_installation.ci
  id = "my-enterprise:my-organization:Iv23liAbCdEfGhIjKlMn"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
terraform import github_enterprise_organization_app_installation.ci my-enterprise:my-organization:Iv23liAbCdEfGhIjKlMn
```
