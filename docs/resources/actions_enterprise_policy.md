# github_actions_enterprise_policy (Resource)

Manages a GitHub Actions policy at the Enterprise level, including workflow lockfile requirements, allowed actors, and allowed events.

This resource uses the [GitHub Actions policies REST API](https://docs.github.com/en/enterprise-cloud@latest/rest/actions/policies) and requires enterprise owner access using an OAuth token or a personal access token (classic). Evaluate mode requires GitHub Enterprise Cloud.

Each resource manages a single policy defined at the enterprise level. Inherited policies must be managed at their source.

~> An active lockfile requirement blocks targeted workflows that have not been onboarded to their repository's workflow dependency lockfile. Start with `evaluate` while onboarding workflows. See [Enforcing lockfiles for action dependencies](https://docs.github.com/en/actions/how-tos/administer/enforce-workflow-lockfiles).

Omit `workflow_path` to target all workflows. Removing a configured `workflow_path` block resets targeting to all workflows. To restrict workflows by exclusion alone, set `exclude` and leave `include` empty. `~ALL` cannot be excluded or combined with other included workflow patterns.

An empty `restrict_actions_actors` or `restrict_action_events` block blocks all actors or events, respectively. Remove the block to remove that restriction. Actor and event collections are unordered.

The `conditions` block must combine exactly one organization target (`organization_name`, `organization_id`, or `organization_property`) with exactly one repository target (`repository_name` or `repository_property`).

## Example Usage

```terraform
resource "github_actions_enterprise_policy" "example" {
  enterprise_slug = "example-enterprise"
  name            = "Workflow security"
  enforcement     = "evaluate"

  conditions {
    organization_name {
      include = ["example-org"]
    }
    repository_name {
      include = ["service-*"]
    }
    workflow_path {
      include = [".github/workflows/*.yml"]
      exclude = [".github/workflows/legacy.yml"]
    }
  }

  rules {
    require_lockfile = true

    restrict_actions_actors {
      allowed_actors {
        id   = 5
        type = "RepositoryRole"
      }
      allowed_actors {
        id   = 12345
        type = "App"
      }
    }

    restrict_action_events {
      allowed_events = ["push", "pull_request", "workflow_dispatch"]
    }
  }
}

# Select organizations by ID and repositories by property.
resource "github_actions_enterprise_policy" "organization_ids" {
  enterprise_slug = "example-enterprise"
  name            = "Selected organization lockfiles"
  enforcement     = "disabled"

  conditions {
    organization_id {
      organization_ids = [123456]
    }
    repository_property {
      include {
        name            = "visibility"
        source          = "system"
        property_values = ["private"]
      }
    }
  }

  rules {
    require_lockfile = true
  }
}

# Target organizations using enterprise custom properties.
resource "github_actions_enterprise_policy" "organization_properties" {
  enterprise_slug = "example-enterprise"
  name            = "Engineering workflow lockfiles"
  enforcement     = "disabled"

  conditions {
    organization_property {
      include {
        name            = "division"
        property_values = ["engineering"]
      }
      exclude {
        name            = "environment"
        property_values = ["sandbox"]
      }
    }
    repository_name {
      include   = ["~ALL"]
      exclude   = ["legacy-*"]
      protected = true
    }
  }

  rules {
    require_lockfile = true
  }
}
```

## Import

Import a policy using the enterprise slug and numeric policy ID, separated by a colon.

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
import {
  to = github_actions_enterprise_policy.example
  id = "example-enterprise:10894"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
terraform import github_actions_enterprise_policy.example example-enterprise:10894
```
