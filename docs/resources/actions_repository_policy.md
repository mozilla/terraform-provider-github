# github_actions_repository_policy (Resource)

Manages a GitHub Actions policy at the Repository level, including workflow lockfile requirements, allowed actors, and allowed events.

This resource uses the [GitHub Actions policies REST API](https://docs.github.com/en/enterprise-cloud@latest/rest/actions/policies) and requires repository administration write permission. Evaluate mode requires GitHub Enterprise Cloud.

Each resource manages a single policy defined at the repository level. Inherited policies must be managed at their source.

~> An active lockfile requirement blocks targeted workflows that have not been onboarded to their repository's workflow dependency lockfile. Start with `evaluate` while onboarding workflows. See [Enforcing lockfiles for action dependencies](https://docs.github.com/en/actions/how-tos/administer/enforce-workflow-lockfiles).

Omit `workflow_path` to target all workflows. Removing a configured `workflow_path` block resets targeting to all workflows. To restrict workflows by exclusion alone, set `exclude` and leave `include` empty. `~ALL` cannot be excluded or combined with other included workflow patterns.

An empty `restrict_actions_actors` or `restrict_action_events` block blocks all actors or events, respectively. Remove the block to remove that restriction. Actor and event collections are unordered.

## Example Usage

```terraform
resource "github_actions_repository_policy" "example" {
  repository  = "example"
  name        = "Workflow security"
  enforcement = "evaluate"

  conditions {
    workflow_path {
      include = [".github/workflows/*.yml"]
      exclude = [".github/workflows/legacy.yml"]
    }
  }

  rules {
    require_lockfile = true

    restrict_actions_actors {
      allowed_actors {
        id   = 5
        type = "RepositoryRole"
      }
      allowed_actors {
        id   = 12345
        type = "App"
      }
    }

    restrict_action_events {
      allowed_events = ["push", "pull_request", "workflow_dispatch"]
    }
  }
}
```

## Import

Import a policy using the repository name and numeric policy ID, separated by a colon.

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
import {
  to = github_actions_repository_policy.example
  id = "example:10894"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

terraform import github_actions_repository_policy.example example:10894
